# 接口对照说明 — 文档编写模块（doc_page.py → HTML）

> 源文件：`pages/doc_page.py`  
> 目标页面：`html_files/home-page.html`（与对话模块同页）  
> **认证方式、公共约定、现有接口规范**：见 [接口对照说明_对话模块.md](./接口对照说明_对话模块.md)，本文不重复。

---

## 一、复用的已有接口

| 场景 | 复用接口 | 说明 |
|---|---|---|
| 文档生成完成后刷新侧边栏历史 | `GET /api/conversations` | `_auto_save_document` 服务端自动创建对话记录后，前端调同一接口刷新列表 |
| 点击历史对话中的文档记录 | `GET /api/conversations/{id}/messages` | 文档记录以普通对话消息存储，复用同一接口读取 |
| 退出登录 | `POST /api/auth/logout` | 与对话模块完全相同 |

> **服务端复用说明**：`_auto_save_document` 在生成文档后内部调用 `create_conversation()` + `save_message()`，与对话模块共享同一服务层函数，无需新增接口。

## 二、页面状态映射

| Streamlit `session_state` 字段 | 类型 | JS 状态变量 | 说明 |
|---|---|---|---|
| `doc_step` | `"input" \| "outline_review" \| "document_generated"` | `docState.step` | 控制三步流程显示哪个面板 |
| `doc_requirements` | `str` | `docState.requirements` | 用户输入的需求描述 |
| `doc_outline` | `str` | `docState.outline` | AI 生成或用户修改后的目录 |
| `doc_content` | `str` | `docState.content` | 最终生成的文档正文 |
| `doc_generating` | `bool` | `docState.generating` | 是否正在调用 AI（控制 loading 态） |
| `doc_reference_context` | `str` | `docState.referenceContext` | 附件解析后的文本（由服务端返回，随 generate-outline 响应下发） |
| `doc_uploader_key` | `int` | — | Streamlit 专用重置技巧，HTML 中直接 `input.value = ""` 即可，无需对应 |

## 三、函数映射

| Streamlit 函数/操作 | 对应位置 | 说明 |
|---|---|---|
| `_auto_save_document(user, outline)` | 服务端：`POST /api/doc/generate-content` 内部自动执行 | 生成标题 → 保存文档 → 创建对话记录，前端无需单独调用 |
| `reset_doc_state()` | 前端 JS：`resetDocState()` | 清空 `docState` 所有字段，切换显示到 Step 1 面板 |
| `generate_title_from_requirements(outline)` | 服务端内部调用 | 不暴露为独立接口 |
| `extract_file_content(f, max_chars=8000)` | 服务端：`POST /api/doc/generate-outline` 内部处理 | 附件 multipart 上传后由服务端解析，前端只传文件二进制 |
| `chat_direct("doc_agent", outline_prompt, ...)` | `POST /api/doc/generate-outline` | Step 1 生成目录 |
| `chat_direct("doc_agent", content_prompt, ...)` | `POST /api/doc/generate-content` | Step 2 生成文档正文 |
| `require_login()` / `require_role(["user","admin"])` / `get_current_user()` | 见对话模块文档 — JWT 中间件 + `localStorage` | 完全复用，无差异 |

## 五、新增 API 接口规范

### `POST /api/doc/generate-outline`

**触发**：Step 1 点击「生成目录」

**请求**：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `requirements` | `string` | 是 | 用户需求描述文本 |
| `files` | `File[]` | 否 | 用户上传的参考附件（多文件） |

**响应** `200 OK`：`application/json`

```json
{
  "outline": "# 一、...\n## 1.1 ...",
  "steps_log": ["step1 description", "step2 description"],
  "reference_context": "=== 用户上传附件 ===\n[附件1：xxx.pdf]\n..."
}
```

| 字段 | 前端处置 |
|---|---|
| `outline` | 写入 `docState.outline`，填入 Step 2 编辑框 |
| `steps_log` | 展示在「查看生成过程」`<details>` 中 |
| `reference_context` | 存入 `docState.referenceContext`，随 generate-content 请求原样转发 |

---

### `POST /api/doc/generate-content`

**触发**：Step 2 点击「确认目录，生成文档」

**请求**：`application/json`

```json
{
  "requirements": "用户原始需求",
  "outline": "用户确认/修改后的目录",
  "reference_context": "附件解析文本（可为空字符串）"
}
```

**响应** `200 OK`：`application/json`

```json
{
  "content": "# 文档标题\n\n## 一、...",
  "steps_log": ["..."],
  "document_id": 42
}
```

| 字段 | 前端处置 |
|---|---|
| `content` | 写入 `docState.content`，进入 Step 3 展示 |
| `steps_log` | 展示在「查看生成过程」`<details>` 中 |
| `document_id` | 记录用（可选，暂不需前端展示） |

**服务端内部流程**（不暴露给前端）：

```
验证 JWT → 组装 content_prompt
→ chat_direct("doc_agent", content_prompt, ...)
→ _auto_save_document()
    ├─ generate_title_from_requirements()
    ├─ save_document()
    └─ create_conversation() + save_message() × 2   ← 复用对话模块服务层
→ log_event("doc_generate")
→ 返回 content / steps_log / document_id
```
