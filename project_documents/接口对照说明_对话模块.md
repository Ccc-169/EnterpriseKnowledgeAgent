## 二、新接口规范

### 公共约定

- **Base URL**：`http://localhost:8000`
- **鉴权**：所有 `/api/*` 接口（登录除外）需携带 Header：`Authorization: Bearer <token>`
- **错误格式**：`{"detail": "错误说明"}`，状态码 401（未登录）/ 403（无权限）/ 404（不存在）/ 500（服务错误）

---

### `GET /api/conversations`

获取当前用户的对话列表（按最新更新时间降序）。

**响应 `200 OK`**
```json
[
  {
    "id": 12,
    "title": "公司差旅报销制度...",
    "created_at": "2026-05-31T10:00:00",
    "updated_at": "2026-05-31T10:05:30"
  }
]
```

---

### `POST /api/conversations`

新建对话（空标题，由后续首条消息自动命名）。

**响应 `200 OK`**
```json
{ "id": 13, "title": "新对话" }
```

---

### `DELETE /api/conversations/{id}`

删除对话及其所有消息（级联删除）。

**响应 `200 OK`**
```json
{ "ok": true }
```

**响应 `404`**：对话不存在或不属于当前用户。

---

### `GET /api/conversations/{id}/messages`

获取指定对话的全部消息（升序），同时返回对话标题。

**响应 `200 OK`**
```json
{
  "conversation": { "id": 12, "title": "公司差旅报销制度..." },

    {
      "id": 1,

      "id": 2,

```

### `POST /api/chat/stream` ⭐ 核心接口

发送消息并以 **SSE（Server-Sent Events）** 流式返回思考步骤和最终答案。

**请求体（JSON）**
```json
{
  "message":         "上月考勤异常情况统计",
  "conversation_id": 12,
  "mode":            "data"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `message` | string | 用户输入内容 |
| `conversation_id` | int \| null | 当前对话 ID；`null` 时服务端自动创建新对话 |
| `mode` | string | `"rag"`（知识库检索）/ `"data"`（数据统计）/ `"write"`（仿写） |

**SSE 响应格式**（`Content-Type: text/event-stream`）

每行格式：`data: <JSON>\n\n`

| 事件类型 | 示例 | 触发时机 |
|---|---|---|
| `type:"init"` | `{"type":"init","conversation_id":12,"title":"上月考勤..."}` | 首条消息时返回，含新生成的对话标题 |
| `type:"step"` | `{"type":"step","text":"🔧 调用工具：**lookup_schema**"}` | 每个 LangGraph 工具调用/返回时推送 |
| `type:"answer"` | `{"type":"answer","text":"以下是上月考勤异常汇总：...","warning":false,"agent":"data_agent"}` | 最终回答完成后推送 |
| `type:"done"` | `{"type":"done"}` | 流结束信号，前端关闭 EventSource |
| `type:"error"` | `{"type":"error","text":"执行超时，请重试"}` | 执行异常时推送 |

**服务端内部流程**（不暴露给前端）：
```
验证 JWT
→ 若 conversation_id=null → create_conversation() 返回新 id
→ save_message(role="user")
→ 若标题仍为"新对话" → generate_title_from_message() + update_conversation_title()
→ SSE: type:"init"（含 conversation_id 和 title）
→ 按 mode 调用 chat() 或 chat_direct()
   ├─ 每个 LangGraph node update → SSE: type:"step"
   └─ 收到最终 answer
→ save_message(role="assistant", steps_log, agent_used)
→ log_event("chat", agent_used)
→ SSE: type:"answer"
→ SSE: type:"done"
```

**`mode` 与后端调用的对应关系**：

| mode | 后端调用 | 对应 Streamlit |
|------|----------|----------------|
| `rag` | `chat(input, thread_id, user_context)` | `render_chat_main(user)` 默认路由 |
| `data` | `chat_direct("data_agent", ...)` | `render_chat_main(user, use_direct_agent="data_agent")` |
| `write` | `chat_direct("rag_agent", ...)` | `render_chat_main(user)` 走 rag_agent 仿写 |

## 三、前端 SSE 客户端接入模板

```javascript
async function sendMessage(message, conversationId, mode) {
  const token = localStorage.getItem('token');

  const response = await fetch(`${API_BASE}/api/chat/stream`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer ' + token,
    },
    body: JSON.stringify({ message, conversation_id: conversationId, mode }),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n\n');
    buffer = lines.pop();                      // 保留不完整行

    for (const line of lines) {
      if (!line.startsWith('data: ')) continue;
      const event = JSON.parse(line.slice(6));

      if (event.type === 'init') {
        // 更新 conversation_id 和对话标题
      } else if (event.type === 'step') {
        // 追加思考步骤到折叠区域
      } else if (event.type === 'answer') {
        // 渲染最终回答气泡
      } else if (event.type === 'done') {
        break;
      } else if (event.type === 'error') {
        // 显示错误提示
      }
    }
  }
}
```

> **注**：SSE 使用 `fetch + ReadableStream` 而非 `EventSource`，原因是 `EventSource` 不支持自定义 Header（无法携带 Authorization token）。
