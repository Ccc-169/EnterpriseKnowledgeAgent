> 源函数：`pages/chat_page.py` 中的 `_render_user_settings(user)`  
> 目标页面：`html_files/setting-page.html`  
> **认证方式、公共约定**：见 [接口对照说明_对话模块.md](./接口对照说明_对话模块.md)，本文不重复。

## 一、Streamlit 旧操作与 HTML 新接口对照表

| # | Streamlit 旧操作 | 所在位置 | HTML 新对应 |
|---|---|---|---|
| 1 | `st.text_input("用户名", disabled=True)` | `_render_user_settings` | 页面加载时从 JWT (`localStorage`) 解码读取 `username`，填入只读 `<input>` |
| 2 | `st.text_input("角色", disabled=True)` | `_render_user_settings` | 同上读取 `role`，映射为中文标签，填入只读 `<input>` |
| 3 | `update_display_name(user_id, new_display_name)` | `auth/auth_service.py` | `PUT /api/user/display-name` |
| 4 | `st.session_state.current_user["display_name"] = new_display_name` | `_render_user_settings` | 请求成功后更新 `localStorage` 中 token 解码缓存的展示名，同步刷新侧边栏 `.user-info .name` |
| 5 | `log_event(..., "update_display_name")` | `_render_user_settings` | API 内部自动调用，前端无感知 |
| 6 | `update_password(user_id, old_password, new_password)` | `auth/auth_service.py` | `PUT /api/user/password` |
| 7 | `log_event(..., "update_password")` | `_render_user_settings` | API 内部自动调用，前端无感知 |
| 8 | `st.success(msg)` / `st.error(msg)` / `st.info(msg)` | `_render_user_settings` | 各操作区内联 `<p class="form-msg success/error/info">` 显示提示文案 |
| 9 | `st.rerun()` 刷新侧边栏显示名 | `_render_user_settings` | 无需整页刷新，直接 JS 更新 DOM 中 `.user-info .name` 文本 |
| 10 | `st.button("← 返回对话")` | `_render_user_settings` | `window.location.href = 'home-page.html'`（侧边栏导航已有） |

## 四、新增 API 接口规范

### `PUT /api/user/display-name`

**触发**：点击「保存显示名称」

**请求**：`application/json`（需 `Authorization: Bearer <token>`）

```json
{
  "display_name": "新显示名称"
}
```

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `display_name` | `string` | 是 | 非空、长度 ≤ 50 |

**响应** `200 OK`：

```json
{ "ok": true, "display_name": "新显示名称" }
```

**失败响应**：

| HTTP 状态码 | `detail` | 触发条件 |
|---|---|---|
| `400` | `显示名称不能为空` | 传入空串 |
| `400` | `显示名称长度不能超过 50 个字符` | 超长 |
| `401` | `Token 无效或已过期` | JWT 校验失败 |

**服务端流程**：

```
验证 JWT → 校验字段 → update_display_name(user_id, display_name)
→ log_event("update_display_name") → 返回 { ok, display_name }
```

> 前端收到 `200` 后：将 `.user-info .name` 的文本更新为新显示名称；如需后续请求携带最新名称，可重新存储（token 本身不会被替换，侧边栏只做 DOM 更新即可）。

---

### `PUT /api/user/password`

**触发**：点击「修改密码」（前端校验通过后）

**请求**：`application/json`（需 `Authorization: Bearer <token>`）

```json
{
  "old_password": "旧密码",
  "new_password": "新密码"
}
```

| 字段 | 类型 | 必填 | 校验（前端预校验，后端二次校验） |
|---|---|---|---|
| `old_password` | `string` | 是 | 非空 |
| `new_password` | `string` | 是 | 非空、长度 ≥ 6 |

**响应** `200 OK`：

```json
{ "ok": true }
```

**失败响应**：

| HTTP 状态码 | `detail` | 触发条件 |
|---|---|---|
| `400` | `当前密码错误` | `old_password` 校验不通过 |
| `400` | `新密码长度至少 6 位` | `new_password` 不符合要求 |
| `401` | `Token 无效或已过期` | JWT 校验失败 |

**服务端流程**：

```
验证 JWT → update_password(user_id, old_password, new_password)
→ log_event("update_password") → 返回 { ok }
```

> 修改密码成功后 token 不作废（有效期不变），前端仅显示成功提示，无需重新登录。

## 五、前端校验逻辑（无需请求 API）

| 校验场景 | 条件 | 提示文案 |
|---|---|---|
| 显示名称未修改 | `input.value.trim() === 当前显示名称` | `显示名称未更改` |
| 当前密码为空 | `old_password.value === ""` | `请输入当前密码` |
| 新密码为空 | `new_password.value === ""` | `请输入新密码` |
| 两次密码不一致 | `new_password.value !== confirm_password.value` | `新密码与确认密码不一致` |
| 新密码过短 | `new_password.value.length < 6` | `新密码长度至少 6 位` |
