# 智能体工作流说明

> 版本：当前版本 | 日期：2026-05-27

---

## 架构总览

系统基于 **LangGraph Supervisor（路由器）** 架构，由一个 Supervisor 和三个 Sub-Agent 组成：

```
用户输入 → Supervisor（Router）→ 判断意图 → 转发到对应 Agent → 原样返回答案
```

- **LLM**：Qwen-Plus（阿里云 DashScope），temperature=0，timeout=300s
- **Router**：`create_supervisor`，仅做意图判断和转发，不介入具体业务
- **Sub-Agent**：`rag_agent` / `data_agent` / `doc_agent`，各自为 `create_react_agent` 实现的 ReAct Agent

> **注意**：Supervisor 的 agents 列表只包含 `[rag_agent, data_agent]`。`doc_agent` 不参与 Supervisor 路由，仅通过文档撰写页面 `chat_direct("doc_agent")` 直接调用。

UI 调用路径：

| 模式 | 页面 | 调用方式 | 可用 Agent |
|------|------|---------|-----------|
| 知识库问答 | `index_page` → `render_chat_main()` | `agent.chat()` → Supervisor 路由 | rag / data |
| 数据统计 | `index_page` → `render_chat_main(use_direct_agent="data_agent")` | `agent.chat_direct("data_agent")` | data |
| 文档撰写 | `index_page` → `doc_page` 三步式 UI | `agent.chat_direct("doc_agent")` 分步调用 | doc |

## 1. RAG 知识库问答智能体（rag_agent）

**定位**：企业知识库检索与问答专家。

### 工作流

```
用户问题
  │
  ▼
┌──────────────────────┐
│ 规则安全检查         │ ← 通过 check_user_input()
│ (规则引擎)           │
└──────┬───────────────┘
       │ ✅
       ▼
┌──────────────────────┐
│ 查询改写             │ ← LLM 改写为结构化检索参数
│ (rewrite_query)      │   输出：rewritten_query + keywords + sub_questions
│                      │   短问题（≤10字符或≤3词）跳过改写
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ 首次检索             │ ← 用改写后的 query 调用 Dify 知识库 API
│ (_retrieve_from_dify)│   semantic_search, top_k=10, 无分数阈值, 无重排序
└──────┬───────────────┘
       │ 无结果？
       ▼
┌──────────────────────┐
│ 回退检索             │ ← 用原始 query 重新检索
│ (_retrieve_from_dify)│
└──────┬───────────────┘
       │ 仍无结果？
       ▼
  "知识库中未检索到相关内容"
       │ 有结果？
       ▼
┌──────────────────────┐
│ 生成答案             │ ← LLM 基于检索到的上下文生成回答
│ (_generate_answer)   │
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ 答案质量验证         │ ← LLM 判定：GOOD / HALLUCINATION / NO_CONTEXT / INSUFFICIENT
│ (verify_answer)      │
└──────┬───────────────┘
       │
  ┌────┴─────────────────────────────┐
  │                                  │
  ▼ GOOD                             ▼ HALLUCINATION / INSUFFICIENT
┌────────────────┐          ┌──────────────────────┐
│ 答案后校验      │          │ 重试（最多 1 次）    │
│ (规则引擎)      │          │ 换表达方式重新检索    │
└────┬───────────┘          └──────┬───────────────┘
     │                              │
     ▼                              ▼
  返回最终答案                  返回带警告的答案 / 回退答案
```

### 关键特性

| 特性 | 说明 |
|------|------|
| **查询改写** | 短问题（≤10字符或≤3词）跳过改写；长问题由 LLM 改写为更适合语义检索的形式 |
| **回退检索** | 改写查询无结果时，自动用原始查询重试 |
| **答案验证** | 每次生成后由 LLM 判断质量，GOOD 则直接通过，HALLUCINATION/INSUFFICIENT 则重试最多 1 次；NO_CONTEXT 直接返回"未找到" |
| **规则引擎** | 输入安全校验 + 输出质量校验（检测技术错误暴露等） |
| **工具** | `rag_search`（检索+生成一体，内置改写/验证/重试）、`list_kb_documents`（查看知识库文档列表） |

### 适用场景

- 公司制度、规定、政策、员工手册查询
- 文档内容总结、仿写参考
- 知识性问题、公司背景、业务介绍
- 咨询建议类问题（如文档管理方案、技术方案建议等）
- 查询知识库有哪些文档

## 2. Data 数据分析智能体（data_agent）

**定位**：企业 Excel 数据统计分析专家。

### 工作流

```
用户问题（如"统计各部门出勤率"）
  │
  ▼
┌──────────────────────┐
│ 规则安全检查         │ ← 通过 check_user_input()
│ (规则引擎)           │
└──────┬───────────────┘
       │ ✅
       ▼
┌──────────────────────┐
│ Step 1: list_files   │ ← 列出数据目录下所有 Excel/CSV 文件
│                      │
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ Step 2: inspect_file │ ← 读取文件原始前 10 行 + header=0 列名
│                      │   让 LLM 判断表头所在行号
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ Step 3:              │ ← 根据自然语言需求生成 Python 代码
│ execute_data_query   │   传入 query + file_path + skiprows
│                      │
│  ┌─────────────────┐ │
│  │ LLM 生成代码     │ │ ← 含缓存（同文件+同skiprows+同query复用）
│  └───────┬─────────┘ │
│          ▼            │
│  ┌─────────────────┐ │
│  │ 代码安全校验     │ │ ← check_generated_code()，拦截危险操作
│  │ (规则引擎)       │ │   (os.system/eval/subprocess 等)
│  └───────┬─────────┘ │
│          ▼ ✅         │
│  ┌─────────────────┐ │
│  │ 沙箱执行         │ │ ← 发送到独立 Python 执行服务
│  │ (Executor 服务)  │ │   POST /execute_batch 或 /execute
│  └───────┬─────────┘ │
│          ▼            │
│      返回 JSON 结果    │
└──────────────────────┘
       ▼
    Agent 整理输出
```

### 关键特性

| 特性 | 说明 |
|------|------|
| **三步工具链** | `list_files` → `inspect_file` → `execute_data_query`，必须按序调用 |
| **LLM 生成代码** | 根据自然语言需求 + 真实列名 + skiprows 生成 Pandas 统计代码 |
| **代码缓存** | 同一文件 + 同 skiprows + 同 query 的代码结果复用，避免重复 LLM 调用 |
| **沙箱执行** | 代码在独立 Executor 服务中运行，与主服务隔离 |
| **安全校验** | 规则引擎拦截 `os.system`/`eval`/`subprocess` 等危险调用 |
| **多文件支持** | file_path 支持逗号分隔多个文件，自动合并 + `_source_file` 标记来源 |
| **硬编码兜底** | 正则后处理：将 LLM 可能硬编码的文件名替换为 DATA_PATH 变量 |
| **TCP 连接复用** | 使用 `requests.Session()` 复用 HTTP 连接（~2s → <10ms） |

### 适用场景

- 考勤统计（出勤率、迟到次数、工作时长）
- 排名、汇总、均值计算
- 跨月数据对比、趋势分析
- 条件筛选、全年综合分析

## 3. Doc 文档编写智能体（doc_agent）

**定位**：企业文档撰写专家。

> **重要变更**：doc_agent 已从 Supervisor 路由中移除，仅通过文档撰写页面（`doc_page`）直接调用。

### 工作流（文档撰写页面分步调用）

```
Step 0: 输入页面
  ├─ 用户输入文档需求
  ├─ 可选：上传参考附件（自动解析内容）
  ├─ 可选：知识库检索（自动检索相关文档）
  └─ 点击"生成目录"
       │
       ▼
Step 1: 目录确认页
  ├─ 展示 LLM 生成的文档目录
  ├─ 用户可编辑修改目录
  ├─ 可选：再次上传附件补充参考
  └─ 点击"确认目录，生成文档"
       │
       ▼
    ┌──────────────────────────────┐
    │ chat_direct("doc_agent",     │
    │   "任务：生成文档内容\n"       │
    │   "原始需求：{requirements}\n" │
    │   "已确认的目录：{outline}\n"  │
    │   "参考上下文：{context}")    │
    └──────────────┬───────────────┘
                   ▼
          ┌───────────────────┐
          │ search_knowledge_ │ ← 检索知识库参考文档
          │ base              │
          └───────┬───────────┘
                  ▼
          ┌───────────────────┐
          │ generate_document │ ← 逐章节生成
          │ _content          │   _parse_sections() 解析目录
          │                   │   每章独立生成（带前文衔接）
          │                   │   最后拼接 + 质量校验
          └───────┬───────────┘
                  ▼
Step 2: 文档展示页
  ├─ 展示完整文档
  ├─ 自动保存到数据库 + 创建侧边栏对话记录
  ├─ 支持复制/下载
  └─ 支持"新建文档"或"返回首页"
```

### 逐章节生成逻辑（generate_document_content）

```
目录 Markdown
  │
  ▼
_parse_sections(outline)
  │  提取 ##（一级章节）+ ###（二级标题）
  │  自动去除章节名后的描述说明（"—— 内容说明"）
  │
  ▼
for 每个章节:
  │
  ├─ 构造 prompt：SECTION_PROMPT
  │  + 参考上下文 + 原始需求 + 完整目录 + 当前章节 + 二级标题列表 + 前文衔接
  │
  ├─ LLM 生成该章节内容（带重试：最多 3 次，指数退避 2^n 秒）
  │
  └─ full_doc_parts.append(section_content)
  │
  ▼
"\n\n".join(full_doc_parts) → 完整文档
  │
  ▼
答案质量后校验（规则引擎）
```

### 关键特性

| 特性 | 说明 |
|------|------|
| **知识库检索** | 生成前先检索 Dify 知识库获取参考文档，作为撰写依据（top_k=5，限 4000 字符） |
| **目录先行** | 先出目录给用户确认，确认后再生成正文（避免一次生成不符合预期） |
| **逐章节生成** | 将大文档拆分为逐章独立生成，降低单次 LLM 压力，提高内容质量 |
| **前文衔接** | 每章生成时传入前两章内容，保证逻辑连贯 |
| **LLM 重试** | `_invoke_with_retry()` 带指数退避（2^n 秒），处理 API 连接超时 |
| **规则引擎** | 答案后校验，检测技术错误暴露等问题 |
| **目录解析** | `_parse_sections()` 自动提取一级/二级标题，去除补充说明文字 |
| **单次调用** | Agent prompt 强制"一次调用只执行一个阶段"，不跨阶段操作 |

### 工具

| 工具 | 说明 |
|------|------|
| `search_knowledge_base` | 检索 Dify 知识库，获取参考文档片段 |
| `generate_document_outline` | 根据需求 + 参考上下文生成文档目录 |
| `generate_document_content` | 根据目录 + 需求 + 参考上下文逐章节生成完整文档 |
| `improve_document_outline` | 根据用户反馈修改目录 |

### 适用场景

- 编写文档、报告、方案、手册
- 规章制度、工作流程编写
- 工作总结、汇报材料
- 文档目录/大纲生成

## 4. Supervisor 路由分发逻辑

Supervisor 根据用户问题自动判断意图并转发（仅 `rag_agent` 和 `data_agent`）：

| 问题类型 | 转发至 | 触发条件 |
|---------|--------|---------|
| 知识问答 | `rag_agent` | 文档内容提问、制度查询、总结文档、仿写、知识库查询、咨询建议类问题 |
| 数据分析 | `data_agent` | 统计排名汇总、考勤分析、Excel 文件处理、跨月对比 |

> **doc_agent 不参与 Supervisor 路由**，仅通过文档撰写页面直接调用。用户在知识库问答模式下的写作类需求（如"帮我总结""怎么写方案"）由 `rag_agent` 基于 LLM 知识直接回答。

**Supervisor 严格规则**：

1. 只做判断和转发，最多做**两次转发**（首次失败可换一个 Agent 再试）
2. 达到两次转发后，即使 Agent 返回的是"未找到相关内容"，也必须原样返回并结束
3. 禁止对 Agent 的回答进行二次总结、改写或压缩
4. 禁止在 Agent 回答之外添加任何补充说明
5. 任务完成即结束，禁止反复路由

## 5. 共享机制

| 机制 | 说明 |
|------|------|
| **规则引擎** | 所有 Agent 共享：输入安全校验（`check_user_input`）、输出质量校验（`check_generated_answer`/`check_generated_code`） |
| **LLM** | 三个 Agent 共享同一个 Qwen-Plus 模型实例（temperature=0, max_tokens=8192） |
| **Dify 知识库** | `rag_agent` 和 `doc_agent` 共用同一套 Dify API（相同 KB ID），检索参数各自独立 |
| **用户上下文** | `user_context`（user_id, username, role）贯穿 Supervisor 和 Sub-Agent |
| **Thread ID** | 每个 Agent 支持多轮对话记忆（基于 `MemorySaver` 和 `thread_id`） |
| **HTTP 连接** | `data_agent` 的 Executor 调用使用 `requests.Session()` 复用 TCP 连接 |

## 6. Agent 注册与权限

通过 `agents/registry.py` 统一管理：

| Agent | 名称 | 权限 | 状态 |
|-------|------|------|------|
| `rag_agent` | RAG 知识库智能体 | user, admin | enabled |
| `data_agent` | Data 数据分析智能体 | user, admin | enabled |
| `doc_agent` | Doc 文档编写智能体 | user, admin | enabled |

未来扩展只需在 `AGENT_REGISTRY` 中注册，无需修改 `agent.py`。
