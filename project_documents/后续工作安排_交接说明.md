# HNGD 企业智能助手 — 后续工作安排交接说明

> 文档日期：2026-08-08
> 基于会议总结的 6 项待优化内容整理

---

## 一、项目当前概况

平台已完成 4 类智能体（知识问答、数据分析、文档撰写、API 调用）、Supervisor 路由分发、JWT 认证、审计日志、代码沙箱、规则引擎等底座能力，前端 14 个页面功能齐全。当前主要瓶颈集中在：单模型硬编码无法切换、对话严格串行多用户排队体验差、文档生成逐章顺序执行效率低、数据接口导入缺少鉴权、4 卡 GPU 未充分利用。

---

## 二、六项待优化内容

### 1. 文档撰写工作流优化

**问题**：当前文档生成是逐章顺序调用大模型，5 个章节就是 5 次串行等待，一份文档耗时约 40 秒。同时每章 prompt 都携带完整目录和上下文，存在大量冗余 token 消耗。

**优化方向**：将逐章串行改为章节间并行生成，并精简每章的 prompt（仅保留当前章节信息），利用多 GPU 并发能力缩短文档生成耗时。短章节可合并为一次调用，通用章节（前言、结语）可缓存复用。


---

### 2. 服务器 GPU 运行情况分析

**问题**：服务器有 4 张 GPU 卡，但当前只用了 1 张跑模型，其余 3 张空闲。需要先搞清楚：当前回答慢的瓶颈到底在 GPU 推理侧，还是在知识库检索或网络 IO 侧。

**工作内容**：在服务器上采集 GPU 的空闲基线和负载数据，分别测试单请求、文档生成、并发请求三种场景下的 GPU 利用率、显存占用和延迟分布，最终输出一份 GPU 分析报告，明确瓶颈位置和优化建议。


---

### 3. 数据接口导入鉴权

**问题**：当前从 Swagger 或 JSON 导入数据接口时，只做了格式校验，没有任何鉴权。导入的接口规范包含内部 API 的完整路径和参数结构，若被未授权导入，存在信息泄露风险。

**优化方向**：为接口导入增加两层鉴权——操作层要求 admin 角色才能执行导入，数据源层要求在导入时提供访问 Token，写入数据库后供后续 API 调用时使用。

---

### 4. 多用户对话并行处理

**问题**：当前对话并发数设为 1（对齐 Ollama 的单线程模式）。

**优化方向**：优化多用户多个对话任务的并行处理。


---

### 5. 用户自主选择与切换大模型

**问题**：当前模型硬编码为本地 Ollama 的 qwen3.6:35b，用户无法切换模型厂商或版本，也无法按任务选择不同规模的模型（简单问答用小模型，复杂文档用大模型）。

**优化方向**：建设模型配置中心，支持注册多个模型（本地 Ollama 不同版本、云端 API 不同厂商）。前端对话页增加模型选择器，用户可按需切换，选择结果持久化到用户偏好。

---

### 6. 接入成熟 Skills 并建设可视化管理页面

**优化方向**：可尝试接入社区已有的成熟 Skills，复用已经成熟的skills，减少重复开发。在本平台建设一个 Skills 管理平台，支持浏览、安装、启用/停用外部 Skill，提供可视化操作页面。
