## 产品概述

为企业知识库智能体系统新增对话记录持久化功能，支持用户创建、查看、切换和删除对话记录。前端侧边栏改造为类似 ChatGPT 的对话记录列表样式，原有用户信息和管理功能移至合适位置。

## 核心功能

- 对话记录持久化：每次对话独立保存，包含对话标题、创建时间、更新时间
- 对话记录管理：新建对话、切换对话、删除对话、编辑对话标题
- 侧边栏改造：显示对话记录列表，支持搜索、新建对话按钮
- 用户信息展示：移至侧边栏顶部，包含用户名称、角色标签
- 退出登录：移至侧边栏底部
- 多轮对话支持：每个对话独立维护 LangGraph 的 thread_id 和消息历史

## 技术栈选择

- 后端：继续沿用 Python + SQLite + Streamlit
- 数据库：SQLite，在现有 `hngd.db` 中新增两张表
- 前端：Streamlit（保持现有架构）

## 实现方案

### 数据表设计

采用单表设计（所有用户共用两张表），通过 `user_id` 字段区分用户：

**conversations 表**（对话记录表）

- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `user_id` INTEGER NOT NULL
- `title` TEXT NOT NULL DEFAULT '新对话'
- `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- FOREIGN KEY (user_id) REFERENCES users(id)

**messages 表**（消息表）

- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `conversation_id` INTEGER NOT NULL
- `role` TEXT NOT NULL（'user' 或 'assistant'）
- `content` TEXT NOT NULL
- `steps_log` TEXT（JSON 格式存储推理过程，可为空）
- `agent_used` TEXT（记录使用的 Agent 名称）
- `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE

**设计理由**：

- 一个用户一张表会导致表数量爆炸，难以维护
- 用 `user_id` 区分用户，配合索引查询高效
- 符合关系型数据库第三范式，易于备份和迁移
- 使用 FOREIGN KEY + CASCADE 删除，自动清理关联消息

### 模块划分

**新增模块：conversation_service.py**

- `create_conversation(user_id, title)` → 创建新对话，返回 conversation_id
- `get_conversations(user_id, limit, offset)` → 获取用户的对话列表（按 updated_at 降序）
- `get_conversation(conversation_id, user_id)` → 获取单个对话信息（验证权限）
- `update_conversation_title(conversation_id, user_id, title)` → 修改对话标题
- `delete_conversation(conversation_id, user_id)` → 删除对话（级联删除消息）
- `save_message(conversation_id, role, content, steps_log, agent_used)` → 保存单条消息
- `get_messages(conversation_id, user_id)` → 获取对话的所有消息
- `update_conversation_timestamp(conversation_id)` → 更新对话的 updated_at

**修改模块：**

1. **core/database.py**

- 新增 `_CREATE_CONVERSATIONS_TABLE` 和 `_CREATE_MESSAGES_TABLE` SQL 语句
- `init_db()` 函数中添加这两张表的创建逻辑

2. **pages/chat_page.py**

- 侧边栏改造：显示对话列表、新建对话按钮、搜索框
- 主区域：根据选中的对话加载消息历史
- 发送消息时：保存到数据库、更新对话时间戳
- 新建对话时：创建数据库记录、清空消息区域
- 切换对话时：加载该对话的历史消息

3. **app.py**

- 侧边栏布局调整：移除原有侧边栏导航，改为在 chat_page 中统一管理
- 保持 "对话" / "管理后台" 的页面路由逻辑

4. **agent.py**（可选修改）

- `chat()` 函数新增 `conversation_id` 参数，用于生成唯一的 thread_id
- thread_id 格式改为 `conversation-{conversation_id}`，实现每对话独立记忆

### 数据流设计

**新建对话流程**：

1. 用户点击"新建对话"按钮
2. 调用 `create_conversation()` 创建数据库记录
3. 生成 thread_id = `conversation-{conversation_id}`
4. 清空当前消息显示
5. 侧边栏高亮新对话

**发送消息流程**：

1. 用户输入消息
2. 调用 `agent.chat()` 获取回复（使用当前对话的 thread_id）
3. 调用 `save_message()` 保存用户消息和助手回复
4. 调用 `update_conversation_timestamp()` 更新时间戳
5. 如果是第一条消息，用用户问题生成对话标题（截取前20字）
6. 侧边栏更新对话列表（按 updated_at 重排）

**切换对话流程**：

1. 用户在侧边栏点击某个对话
2. 调用 `get_messages()` 加载该对话的历史消息
3. 设置当前 thread_id = `conversation-{conversation_id}`
4. 主区域显示历史消息

### 性能优化

- 对话列表查询添加 `LIMIT` 分页，避免加载全部历史
- messages 表对 `conversation_id` 建索引（FOREIGN KEY 自动创建）
- 消息内容使用 Streamlit 的 `st.chat_message` 渲染，避免重复渲染
- 对话标题自动生成：取第一条用户消息的前20字符，避免调用 LLM

## 实现注意事项

1. **权限验证**：所有对话操作必须验证 `user_id`，防止横向越权
2. **向后兼容**：现有用户首次使用时，自动创建"默认对话"记录
3. **LangGraph 记忆**：每个对话使用独立的 thread_id，确保多轮对话记忆隔离
4. **错误处理**：数据库操作必须放在 try-finally 块中，确保连接关闭
5. **UI 状态同步**：`st.session_state` 中维护当前对话 ID，侧边栏选中状态同步

## 设计风格

采用简约现代风格，参考 ChatGPT 的对话界面布局，确保用户体验流畅直观。

## 页面布局设计

### 整体布局

- **左侧侧边栏**（宽度 300px）：对话记录列表
- **右侧主区域**（剩余空间）：对话界面

### 侧边栏设计（从上到下）

**顶部区域 - 用户信息**

- 显示用户头像（使用首字母）
- 显示用户名称和角色标签（管理员/普通用户/访客）
- 样式：圆角矩形，浅色背景

**中间区域 - 对话列表**

- 顶部："新建对话"按钮（突出显示，+ 图标）
- 搜索框：输入关键词过滤对话标题
- 对话列表：按更新时间降序排列
- 每项显示：对话标题（单行截断）、更新时间（相对时间如"3分钟前"）
- 悬停效果：背景色变化
- 选中状态：高亮显示
- 右键菜单（或长按）：重命名、删除

**底部区域 - 退出登录**

- 退出登录按钮（红色或灰色，低调设计）

### 主区域设计

**顶部**

- 当前对话标题（可点击编辑）
- 对话操作按钮：删除对话、导出对话（可选）

**中间**

- 消息列表：用户消息右对齐，助手消息左对齐
- 助手消息可展开"查看推理过程"

**底部**

- 输入框：固定底部，支持多行输入
- 发送按钮

## 交互设计

- 新建对话：点击按钮 → 清空主区域 → 侧边栏新增项高亮
- 切换对话：点击对话项 → 主区域加载历史消息 → 侧边栏选中项变化
- 删除对话：确认弹窗 → 删除记录 → 自动切换到最新对话或新建对话
- 编辑标题：点击标题 → 输入框出现 → 回车保存
